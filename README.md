# Sankruv Media website

Multi-page website for Sankruv Media, a digital marketing agency in Mumbai.
Static HTML, CSS and JavaScript, generated by one small Python script. It runs on any
hosting (Hostinger, Netlify, GitHub Pages) by uploading the built files.


## React version (`react/`)

The website now also exists as a React app in `react/`. It renders every page to static HTML at build time
(so search engines and slow phones get the full page straight away) and then hydrates it in the browser.
It runs on any static or shared host, including Hostinger: no Node server is needed in production.

```
cd react
npm install
npm run build            # output in react/dist, ready to upload
npm run build:preview    # same, but hidden from search engines
```

| Path | What it holds |
|---|---|
| `react/src/App.jsx` | The app shell and the list of pages |
| `react/src/ui.jsx` | Shared components: header, menu, footer, services, blog rows, and so on |
| `react/src/pages/*.jsx` | One component per page |
| `react/src/Work.jsx` | Films wall and the in-page video player |
| `react/src/effects.js` | Animation engine: scroll effects, reveals and the WebGL 3D scene |
| `react/src/react.css` | Styles added for the React version (base styles stay in `assets/css/site.css`) |
| `react/build.cjs` | Build script: prerender, bundle, sitemap, RSS, robots |
| `content/videos.json` | The films shown on the Work page and the home showreel |

Content is shared with the original build: `content/*.json` and `content/blog/*.md`. To add a film, add one
line to `content/videos.json` (`src` is `youtube`, `drive` for one Drive file, `folder` for a Drive folder, or
`link`). Drive files and folders must be shared as "Anyone with the link" or they will not play on the site.
The Client Hub in `admin/` stays PHP and is copied into the build unchanged.

### Client Hub in React

The Client Hub screens are a React app too: source in `react/admin/` (`main.jsx` shell, dialogs and search; `views.jsx`
dashboard, clients, projects board, reminders, payments, emails; `client.jsx` the client profile; `core.jsx` helpers).
`npm run build` bundles it into `admin/assets/hubapp.js`, which is committed so the hub works on a PHP host without Node.

- `admin/app.php` checks the sign-in and loads the app. `admin/data.php` serves read-only JSON. Changes go through `admin/api.php`.
- Sign-in, first-run setup, password reset and the Team page stay as PHP pages, because passwords are handled on the server.
- `admin/index.php` opens the React hub by default. `index.php?classic=1` switches to the older PHP screens for the session
  (`?classic=0` switches back), or set `'ui' => 'classic'` in `admin/config.php`.

The original static generator (`build.py`, `src/`) is kept untouched as a fallback until the React version goes live.

## Quick start

```bash
python3 build.py              # builds every page into this folder
python3 build.py --out dist   # or builds a clean copy into ./dist for upload
```

Python 3.8 or newer is all that is needed. If Pillow is installed (`pip install pillow`),
each blog article also gets its own share image for WhatsApp, LinkedIn and Facebook.

## Adding a blog article (daily posting)

1. Copy `content/blog/_template.md` and rename it, for example `content/blog/how-to-plan-reels.md`.
   The file name becomes the address: `blog/how-to-plan-reels.html`.
2. Fill in the title, description, date, category and a higher `order` than the newest article.
3. Write the article in Markdown (the template shows headings, lists, bold and links).
4. Run `python3 build.py` and upload, or push to GitHub if hosting deploys from the repository.

The build updates the blog page, the home page's latest articles, related articles, the sitemap
and the RSS feed (`blog/feed.xml`) automatically. Every article stays on this website.

## The 3D scene

One WebGL canvas sits behind every page. Each section carries a `data-fx` attribute with seven
numbers, `x y scale split hue dim model`, describing the 3D object while that section is in the
middle of the screen. With `data-anchor` the object moves into an element inside the section
(the hero orb under the headline, the sticky service stage, page heroes, the closing section).

| Model | Shape | Where |
| --- | --- | --- |
| 0 | Brand core; with `split` it separates into four service solids | Home hero, services hero, closing sections |
| 1 | Linked rings | About, testimonials |
| 2 | Stacked screens | Websites, work |
| 3 | Cut gem | Branding, reasons |
| 4 | Lattice sphere | Process sections |
| 5 | Signal rings | Social media, contact |
| 6 | Camera lens | Shoots, FAQ, video articles |

The render resolution drops automatically on slower devices, and visitors who turn on reduced
motion get still frames.

## Contact form

The three-step brief posts to `admin/lead.php` (set in `data-endpoint` in `src/pages/contact.html`).
Each enquiry becomes a **new lead** in the Client Hub, with the full brief in its history and a
high-priority reminder to reply the next day. The visitor still gets the WhatsApp and email buttons,
so nothing is lost if the server is down. A hidden `website` field catches spam bots.

## Client Hub (admin)

A private team workspace at `/admin/` (PHP 8 + SQLite, no database server needed).

| Page | What it does |
|---|---|
| `index.php` | Dashboard: today's reminders, deadlines, pipeline, new leads, payments due, recent activity |
| `clients.php` | Every client as a card, with status filters, sort, quick filter and CSV export |
| `client.php` | The client profile: details edited in place, services, notes, projects, reminders, payments, history |
| `projects.php` | Board by stage. Drag a card to change its stage |
| `reminders.php` | Overdue, today, tomorrow, this week, later and completed |
| `payments.php` | To collect, overdue and received, with monthly and yearly totals |
| `team.php` | Owners add or disable team accounts; everyone can change their own password |

**First run.** Open `/admin/`. It goes to a one-time setup page that asks for a code. The server
writes that code to `setup-code.txt` in the hub's data folder: `sankruv-client-hub-data` next to
`public_html` when the host allows it, otherwise `admin/data/`. Open the file with the hosting file
manager, copy the code, and create the owner account. The file is deleted afterwards.

**Forgotten password.** Put a long random `reset_key` in `admin/config.php` and open
`/admin/reset.php?key=<that value>`. Pick the account, type a new password and you are signed in.
The link works once; set a new key for another reset.

**Install as an app.** On a phone, open the hub and choose "Add to Home screen" (Android) or
Share, then "Add to Home Screen" (iPhone). It opens full screen with its own icon. The service worker
caches only styles, scripts and icons, never pages or client data. The same manifest can be wrapped
as an Android app later (for example with Bubblewrap or PWABuilder).

**Client emails.** Twelve branded emails live in `admin/emails/` (tables and inline styles, safe for
Gmail, Outlook, Apple Mail and phones). They share one design: the logo centred on a dark brand band,
a headline, a highlighted amount where it matters, and a footer with WhatsApp and call buttons.
`tools/gen_emails.py` regenerates them all from one file if you want to change the design or wording.

| Template | When it is used |
|---|---|
| `enquiry-received` | Thank you to a website enquiry (automatic) |
| `welcome` | Welcome a new client (optional automatic when a lead becomes Active) |
| `proposal-sent` | Proposal or quotation with scope, dates and investment |
| `project-confirmed` | Project confirmation with service, dates and value |
| `meeting-confirmed` | Meeting or call confirmation (details go in the personal note) |
| `payment-request` | Ask for an invoice, advance or retainer, with payment details |
| `payment-reminder` | Polite reminder for a due or overdue payment |
| `payment-received` | Receipt when a payment is marked as paid (automatic) |
| `renewal-reminder` | Monthly retainer renewal notice |
| `monthly-report` | Monthly results (highlights or report link in the personal note) |
| `project-delivered` | Delivery note with a review request (optional automatic) |
| `feedback-request` | Ask a happy client for a review or feedback |

Every email can carry an optional personal note from the team member who sends it.
The team sends any of them from a client's profile ("Send email", or the send icon on a project or
payment). The **Client emails** page previews every template. Sending is off until the `mail` block in
`admin/config.php` is filled in: copy it from `config.sample.php`, set `enabled` to `true` and add the
SMTP mailbox (Hostinger: `smtp.hostinger.com`, port 465, `ssl`, full mailbox address and its password).
Also set `public_url` so the logo and links in emails point to the live site, and fill in
`payment_info` and `review_url`. Every email sent is recorded in the client's History.

To edit wording, open the template file. `{{first_name}}` style tags are filled in for you, and
`{{#name}}...{{/name}}` shows a block only when that value exists. The first comment in each file holds
its subject line and preview text.

**Security.** Every page sends strict security headers (CSP, no framing, HSTS on HTTPS). Sessions
work only in the browser that signed in, end after 8 idle hours, and end everywhere when that
account's password changes. Five wrong passwords lock an account for 10 minutes. Only owners can
export the client list or delete clients. PHP errors are never shown to visitors; they are logged
to `error.log` in the data folder. `test_mode` in config.php allows short test passwords and must be
switched off before real use.

**Data and safety.** The database, sessions and setup code live in the data folder, which is never
committed (see `.gitignore`) and is blocked from the web. Passwords need at least 8 characters. Sign-in uses hashed passwords, CSRF tokens,
rate limits and a 10-minute lock after 5 wrong passwords. Sessions end after 8 idle hours. Pages send
a strict Content Security Policy and `noindex`. Optional settings go in `admin/config.php`
(copy `admin/config.sample.php`). Back up the data folder regularly.

## Before going live

1. **Domain.** Canonical links, the sitemap and structured data use `https://www.sankruvmedia.com/`
   (`url` in `content/site.json`).
2. **Redirects.** Old article addresses were `/post/<name>`. The new ones are `/blog/<name>.html`
   with the same names, so a single redirect rule can carry them over.
3. **WhatsApp number.** The brief form sends to `whatsapp_number` in `content/site.json`
   (918668738331, taken from the published phone number). Confirm it is the WhatsApp number.
4. **Logo.** `assets/img/logo.png` was cropped from a screenshot. Replace it with the original file.
5. **Copy to confirm with the client:** the three testimonials (paraphrased from the old site),
   the About text, FAQ answers, process steps, service deliverable descriptions and the brands list.
6. **Blog articles** were written new on the same topics as the old site's articles.
7. **Projects** use illustrated mockups. Add real photos and more projects in `content/projects.json`.
